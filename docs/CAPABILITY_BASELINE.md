# Capability baseline template

Use before relying on a source feature in an operational instance. Keep source
presence, actual dated observation and missing proof separate. This template
selects no release target and claims no live feature, deployment or approval.

| Capability question | Source evidence to pin | Actual observation to link | Remaining proof |
|---|---|---|---|
| Does the desk distinguish active from expired possession? | Exact reader/caller path, line and full Git ref. | UNKNOWN until an authorized, dated observation is filed. | Record the tested build and limits; a version self-report alone is not behavior proof. |
| Do guarded claims preserve their documented preconditions? | Exact claim boundary and compatibility contract. | UNKNOWN; source-reading is not command execution. | Observe only under a separate applicable runtime grant. |
| Can the exact open handoff be recovered outside a bounded window? | Owning handoff/work-context readers and clipping contract. | UNKNOWN; inspect the actual returned completeness markers. | Preserve unknown visibility and missing-original gaps. |
| Do attachment metadata and downloaded bytes agree? | Storage/publish/download owners and visibility gates. | UNKNOWN; local manifest examples do not prove serving. | Keep uploaded-byte integrity distinct from original custody. |
| Is replay full or partial? | Replay builder, cap, consumer and lineage markers. | UNKNOWN for any unobserved operational build. | Keep partial even after separately recovering a referenced verdict file. |

For every populated row record exact source ref/path/line, evidence locator and
SHA256, observed time with offset, actor observation provenance, actual check/exit,
and UNRUN limits. An empty cell remains UNKNOWN; use no invented values. Link only
appropriately visible/public-safe evidence. Publishing a capability record does
not authenticate an actor, establish independence or confer execution authority.

The source contract can be consulted in [WORK_CONTEXT.md](WORK_CONTEXT.md),
[ACTIVE_WORK.md](ACTIVE_WORK.md), [RUNS.md](RUNS.md) and
[EVIDENCE_MANIFEST.md](EVIDENCE_MANIFEST.md). Existing root/alias design, credentials,
settings and authority remain outside this documentation convention. Apply the
already-authorized release workflow when a concrete target is actually supplied;
this template introduces no new approval gate.
