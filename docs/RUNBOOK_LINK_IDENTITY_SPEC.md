# Saved runbook links survive a rename

Kevin requested this change on 2026-11-17 for conductors and agents sharing runbooks. The independently reproduced baseline is `94f83eee`. An issue and a Mentor page both contained `[[Runbook]]`. After page A was renamed and page B acquired its former title, both browser bodies opened B while the issue's work context and A's backlinks still named A. Editing the source could also replace the stored edge.

## Contract

1. On a successful issue or page body write, bind each distinct authored bare-title token that resolves to a Mentor page to that page's numeric ID. Preserve the authored Markdown. Retain the binding while the token remains in successive saved bodies, including title-only edits, unrelated body edits, duplicate occurrences and replays of the same edit. Removing the last occurrence releases it. Adding it in a later save resolves against the then-current pages. Page version restore follows the same body-edit rule.
2. Use the existing grammar and lookup convention for new tokens. Reserve typed issue/page/user and issue-key tokens exactly as today. Trim bare titles and compare using SQLite NOCASE semantics. Prefer a unique active same-space target for a page source, otherwise require a unique active global target. A fresh unresolved token makes no graph edge. A later deliberate source synchronization may resolve it, including the field guide's second pass. Reads never assign identities.
3. Store per-source token provenance and update it with the outgoing graph in the source transaction. A rename, archive or reuse of a label never reassigns an existing ID. Read the target's current title and apply the same visibility decision as the existing numeric reference. A hidden or deleted target has no clickable anchor or derived label in the body and cannot fall back to a namesake. A visible archived bound page retains ordinary numeric-reference behavior. Preserve section links, embeds, mentions, explicit numeric links, self-edge suppression and the existing work-context response shape.
4. Saved browser issue/page bodies, their edit previews (including restored drafts), and saved bodies in HTML export use the saved identity. A preview uses retained bindings for carried tokens and the normal source-space resolver for newly typed ones. A preview never persists a binding. A source-aware preview checks source access before loading its bindings. A standalone preview has only draft text to resolve. Agent work context, outgoing links and backlinks continue to consume the same graph, with the existing viewer filters.
5. Upgrade existing databases additively. Recover old token identities from positive evidence in the source's existing indexed edges. For example, one distinct bare title and one outgoing page edge unexplained by typed references proves the target, even after a rename. A typed numeric link by itself is insufficient evidence of a bare title's origin. Where earlier deduplication lost the association, keep the token unlinked and avoid binding a current namesake. Preserve previous graph evidence on read. Treat ambiguous retained legacy tokens conservatively on edits, and document how to explicitly repair them. Apply reconciliation to the previously saved body before interpreting an edit. A failed or retried write must leave source, bindings and graph consistent. Deleting a source cleans up its bindings. Deleting a target must never rebind its incoming references.
6. SQLite backups carry the bindings. Selective project/space bundles preserve each exported source's authored body. Replay remaps proven internal title bindings through the page ID map. An omitted external target stays unlinked in the destination, even if it has a namesake and the imported body is subsequently saved unchanged. Older bundles remain readable with conservative legacy reconciliation. Validate optional binding metadata before apply. Bundle contents never supply an unmapped destination ID.

## Verification

- Rehearse the original failure with an installed server, a real database, an issue and a referring page. Check visible anchor IDs, current labels, agent work context and backlinks before and after rename, title reuse, restart and an unrelated edit.
- Exercise new same-space resolution, duplicate and typed links, removal/reintroduction, unresolved forward links, a private or deleted target with a visible namesake, and an unauthorized source preview. Check archives, drafts and HTML export where they render saved bodies.
- Exercise a pre-change database with a renamed runbook and ambiguous deduplicated edges. Confirm that reads leave it untouched, a subsequent edit retains a proven ID, and a failed source transaction rolls back. Verify older and new selective bundles, internal ID remapping and skipped external targets.
- Run the complete local product gate, installed smoke, independent implementation review and hosted pull-request checks before merge. Verify hosted main after merge.

The separate runbook-promotion pointer, historical revision displays, title aliases, global rename redirects and rewrites of other authors' Markdown are outside this change.
